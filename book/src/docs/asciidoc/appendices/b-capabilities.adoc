== Capabilities

Every capability of the Nasdanika SDK that this book names, with its standing as of runtime {runtime-version} and the roadmap of November 2026, and where it is described.
The two books named in the last column are the authority. If this table and one of them disagree, the book is right and this table is stale.

[.available]#AVAILABLE# is in the released runtime.
[.sketch]#SKETCH# has code in the roadmap repository, built and tested.
[.planned]#PLANNED# is designed or intended, and not built on the SDK.

=== Released

[cols="2,4,2",options="header"]
|===
|Capability |In one line |Described in

|Capability framework
|Requirements interpreted by factories, resolved as a graph, with an explanation of what was asked and who declined
|Runtime book, "The capability framework"

|Telemetry
|Every module reports through the OpenTelemetry API. One instance for each unit of work. Published as it happens.
|Runtime book, "Telemetry in the runtime", "Watching work live"

|Telemetry model
|Traces, logs and metrics as models. Changes recorded in the spans that made them.
|Runtime book, "Telemetry as a model"

|Core model
|Identity, documentation as structure, markers of provenance
|Runtime book, "The core model"

|Meta
|A type system with a text syntax, a validator, a glossary and an agent skill
|Runtime book, "Meta: a language-neutral type system"

|Diagrams
|Draw.io as an API and a model, a common diagram model, layout
|Runtime book, "Diagrams"

|Volumes
|A file system interface, served over HTTP and WebDAV
|Runtime book, "Volumes and content"

|Flows
|`Flow` with a pump and a transformer
|Runtime book, "Flows, pumps and transformations"

|Commands and the launcher
|Commands as capabilities, telemetry saved for each run, a trace continued from the environment
|Runtime book, "Commands as capabilities", "Distributions and launching"

|Runtime book, "The JVM model"

=== Not in the SDK

Named in this book as ideas of its own, with no item in the roadmap yet: a prompt as a model of parts, a context as an ordered model of parts, an evaluation suite as a model, and a retrieval module with in-memory search.
Each appears under "Missing" or "To show" in its section, and each would need an item in the roadmap before it is more than that.
